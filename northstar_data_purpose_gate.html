Data Purpose Gate

A team asks to reuse data for a new purpose. The gate checks the request against the approved use profile for that purpose, the readiness of each requested field, and any steward decision still pending. It minimises, holds, blocks or routes the request — with a reason for every field. It never grants access and never decides legality.

Business objective

Reuse critical data only for documented purposes, with only the fields needed, and only when its evidence is current.

Purpose firstNo approved profile, no reuse — route to the owner.
Minimum necessaryFields and retention cut to the profile.
Evidence before reuseA CDE with failing or unknown controls is blocked.

The problem

Approval creep

Approved for billing ≠ approved for everything

Balances approved for billing are requested for marketing or model training. Quality scores and CDE tags never establish permission.

Over-collection

Requests ask for everything

Analysts request whole tables “to be safe”, with long retention. Minimisation happens late, if at all.

Disconnected evidence

Reuse ignores readiness

A field whose lineage is missing or whose test failed is handed to a new consumer because nobody connected the two decisions.
